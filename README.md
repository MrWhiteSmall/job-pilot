# 投递领航 · Job Pilot

本地运行的求职工作台：采集 BOSS 直聘岗位 → 按你的硬条件筛选打分 → 人工/AI 审核入队 → 用**你自己的**浏览器登录态点击「立即沟通」，并在页面上确认结果。数据、简历、登录态全部留在本机。

> 这是自用工具，不是投递代理服务。它只做「在 BOSS 网页上点立即沟通」这一件事：不代填表单、不伪造简历、不绕过验证码、不破解平台限制。使用前请自行确认符合目标平台的服务条款；账号风险由使用者承担。

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Windows 10/11（浏览器复用与截图脚本用到了 Win32 API） |
| Python | 3.10+（开发环境 3.12） |
| 浏览器 | 本机安装的 **Google Chrome**（不下载 Playwright 自带 Chromium） |
| 网络 | 能正常访问 BOSS 直聘；如走代理请确认 `NO_PROXY` 含 `127.0.0.1` |

## 2. 安装与启动

```powershell
git clone https://gitee.com/lushengjie/job-pilot.git
Set-Location job-pilot
python -m pip install -r requirements.txt
python -m pip install pytest          # 只在跑测试时需要
python app.py
```

打开 <http://127.0.0.1:8765>，或双击 `启动投递领航.cmd`。服务只绑定 `127.0.0.1`，不接受外网访问。

首次启动会在 `data/` 下建库并写入一组示例规则（杭州 / AI 应用 / 20–30K），**简历需要你自己填**：要么在「简历」页粘贴文本，要么启动前设置：

```powershell
$env:JOB_PILOT_RESUME = 'D:\你的简历.pdf'
```

## 3. 五分钟上手

1. **简历**：粘贴文本或让程序读取 PDF（`pypdf` 提取，扫描件读不出文字）。
2. **筛选与规则**：按你的真实偏好改城市、职位关键词、薪资、公司规模、学历、招聘性质、黑名单、优先区域，点「保存设置」。
3. **连接 BOSS**：点「连接 BOSS」，会用专用资料目录 `data/boss-chrome-profile/` 打开 Chrome 登录页。**扫码由你本人完成**，程序不代登录、不读取 cookie 文件。
4. **采集新岗位**：登录后点采集；也可导入 CSV/JSON。
5. **批量 AI 分析**（未配模型时走本地规则）→ 看匹配理由、技能命中、风险 →「审核入队」。
6. **先跑模拟**：模式选「模拟」，开托管跑一轮，确认队列与日志符合预期，不会产生任何外部沟通。
7. **切真实模式**：模式选「真实 BOSS」，日上限建议 20–50 起步，间隔 ≥ 60 秒。之后由后台 worker 逐条执行。
8. **随时停**：页面上「立即暂停」/「立即开始」是同一个按钮，双向切换；重启程序默认暂停。

## 4. 规则是怎么生效的

筛选分三层，顺序执行（`engine.match_job`）。字段速查与状态机说明见 [docs/规则说明.md](docs/规则说明.md)：

**① 硬条件（不满足直接淘汰，`score = -1`）**

| 规则 | 字段 | 说明 |
| --- | --- | --- |
| 城市 | `cities` | 只看列表城市包含关键字的岗位 |
| 职位方向 | `titles` / `exclude_titles` | 标题命中 `titles` 才要；命中 `exclude_titles`（产品/销售/讲师/总监…）直接淘汰。比较时会去掉空格，`AI 应用` 能匹配 `AI应用` |
| 薪资 | `min_salary` / `max_salary` | **看区间是否有交集**：`25-45K` 与 20–30 有交集 → 通过；`8-12K`、`35-65K` → 淘汰 |
| 公司规模 | `company_min` / `company_max` | 公司公布区间需**整体**落在范围内：`100-499`、`500-999` 过，`1000-9999` 不过，`0-20` 不过。不公布 → 不淘汰，标「待核验」 |
| 招聘性质 | `recruitment_type = social` | 排除校招/应届/在校/实习/兼职；「接受应届」这类软性措辞不算校招 |
| 学历 | `max_education = 硕士` | 要求博士的淘汰；`本科及以上` 这类「及以上」按本科算，不淘汰 |
| 黑名单 | `blacklist` | 命中公司名即淘汰，用于大厂、外包、猎头 |
| 外包识别 | 内置 | 公司名/描述出现 外包/驻场/派遣/劳务 且没有「非外包/不驻场」澄清 → 淘汰 |
| 公司级去重 | 内置 | 同一公司 30 天内已沟通过（sent/uncertain/blocked），其它岗位不再投 |

**② 打分（0–100，`min_score` 为入队门槛）**

本地打分 = `40 + 60 × (简历与 JD 共同出现的技能数 / 4)`，上限 100。零技能命中 = 40 分，所以门槛设 55 以上能避免「什么都投」。配置了 AI 模型时，由模型给 0–100 分 + 理由 + 风险 + 缺失技能；AI 失败会回退本地分并标记 `local_fallback`，这类结果**不会**被自动审核放行。

**③ 排序（`queue()`）**

按 `(优先区域次序, -分数, id)` 排队：`districts` 里越靠前的区越先投，未列出的区排最后。

## 5. 可选：接自己的模型

兼容 OpenAI Chat Completions 的服务都行（DeepSeek、通义、Kimi、本地 vLLM…）：

```powershell
$env:JOB_PILOT_API_KEY  = 'sk-...'
$env:JOB_PILOT_BASE_URL = 'https://api.deepseek.com/v1'
$env:JOB_PILOT_MODEL    = 'deepseek-chat'
python app.py
```

启用后，**简历全文 + 岗位 JD 会发送到你配置的服务**，页面右上角会显示当前模型。不配置就完全本地运行，不需要联网（除了访问 BOSS）。

其它环境变量：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `JOB_PILOT_DB` | `data/job_pilot.sqlite3` | 数据库位置 |
| `JOB_PILOT_RESUME` | 空 | 启动时自动导入的简历 PDF 路径 |
| `JOB_PILOT_PORT` | `8765` | 服务端口（如支持） |

## 6. 节奏与安全边界

内置的限速是按「像个人」而非「尽可能多」设计的，不建议调快：

- 点击「立即沟通」前随机等 2.6–5.2 秒；
- 两次沟通间隔默认 70 秒，每轮再加 0–16 秒抖动；
- 每 12 次真实沟通休息 5–12 分钟；
- 日上限默认受 BOSS 的 150 次限制，建议先设 20–50 观察一周；
- 单窗口串行，不并发、不多账号；
- 复用真实 Chrome + 专用 profile，抹掉 `navigator.webdriver` 与 console 探测特征；
- 遇到验证码/安全验证/**登录失效**：立即暂停 + 日志告警 + 桌面弹窗，**不尝试绕过**；
- 平台提示「今日沟通上限」等硬限制：暂停，不重试；
- 单条结果无法确认（点击后页面没明确变化）：记为 `uncertain`，**不自动重试**，留给你人工核对；
- 启动真实模式前会先检查登录态，未登录直接拒绝开启。

想让它夜里自己跑，可另开一个窗口用看门狗：`pythonw tools/watchdog.py`。它只做两件事——进程挂了重拉、队列空了补采；遇到平台级暂停（额度/登录/验证码）不会擅自重开，只会记 `data/watchdog.log`。

## 7. 常见问题

**页面打开是空白 / 采集报「未识别岗位卡片」**
多为专用 Chrome 被杀或换了 profile。点「连接 BOSS」复用窗口；仍不行就关掉 `boss-chrome-profile` 对应的 Chrome 进程再重连。

**重启后不投了**
这是设计：`_init_db` 会把 `enabled` 置 0。页面上点「立即开始」即可，启动前会验登录。

**端口被占用 / 改了代码没生效**
旧进程还活着。`Get-CimInstance Win32_Process -Filter "Name='python.exe'"` 看 `CreationDate`，`taskkill /PID <pid> /F` 后再启动。

**改了规则，之前分析的岗位全变回「待分析」**
预期行为：规则或简历一变，非终态岗位的分数与审核都会失效，需要重新分析。

**投出去的消息是什么**
点「立即沟通」发出的是 **BOSS 平台里你自己设置的招呼语**，网页端无法修改它（设置只在 App 里）。「招呼语模板」留空就只发这一条；填了才会在沟通后补发第二条。

**HR 回复了怎么办**
程序不代发回复。聊天页会显示未读，建议人工跟进——这是最有价值的环节。

**换电脑/换账号**
`data/` 整个目录是本地状态（含登录 profile），不要提交、不要外传；换机重新扫码即可。

## 8. 目录结构

```
app.py               Flask 服务、API、worker、AI 分析、告警
engine.py            SQLite 存储、硬筛、打分、队列、去重、日志
browser_adapter.py   Chrome/Playwright 适配：采集、沟通、聊天探测
public/              前端（原生 HTML/CSS/JS，无构建步骤）
tests/               pytest：规则、队列、API、风控、公司去重
tools/               开发与排查脚本（审计、截图、探针、批量分析）
verify_ui.py         已启动服务下的 UI 冒烟（桌面 + 390px）
verify_flow.py       隔离库 + 临时端口的端到端流程
```

## 9. 测试

```powershell
python -m pytest -q      # 35 passed
python verify_ui.py      # 需要服务已启动
python verify_flow.py    # 自起临时服务与隔离数据库，不碰真实数据
```

`tests/conftest.py` 会把 `JOB_PILOT_DB` 指向临时目录，测试不会读写你的真实库，也不会改你的托管开关。
